- LEB128 integer decoding is in-house: a free function takes a byte slice and
  returns the decoded value paired with the number of bytes consumed, so the
  caller advances its own cursor (`read_unsigned`).

- Signed and unsigned variants are separate functions; the signed variant
  sign-extends from the final continuation byte's sign bit.

- The decoder returns its own error type for a truncated stream, which the
  parser maps onto a malformed-module error.

## Facts

- 2024-01-25 (9e801234) rationale: the in-house module was seeded from
  Mohanson's leb128 project (MIT, credited) for its known-good test tables;
  the live decoder is a simple loop, but the file carries a commented-out C
  reference for a fully unrolled read — the stated target the in-house path
  exists to reach, which a crate dependency would not allow without a fork
  (diff).

## Moves

- 2024-01-25 (9e801234) replaced [[leb128-crate]]: the external crate's reader
  is driven through `std::io::Cursor`, forcing the payload reader to wrap
  every slice in a Cursor and re-slice past the consumed bytes; a slice-in,
  (value, consumed)-out function decodes in place with no Cursor and leaves
  room for the planned unrolled fast path (diff).
