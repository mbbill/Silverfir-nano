- LEB128 integers are decoded by in-tree per-width readers
  (`read_leb128_u32`/`i32`/`u64`/`i64`) that accumulate directly into the
  target width and error once the running shift reaches that width's bit count;
  an overlong encoding is rejected at decode rather than by a numeric range
  check afterward.

## Facts

- 2024-03-09 (0439df51) pitfall: rejecting overlong/non-canonical encodings on
  the final byte differs by signedness — for unsigned values the unused high
  bits of the last byte must be zero, but for signed values sign-extension
  means they must be all-zero or all-one matching the sign bit; checking signed
  values like the unsigned case wrongly rejects legitimately sign-extended
  values such as -1 (diff).

## Moves

- 2024-03-08 (f9318ab7) replaced [[width-then-narrow-leb128]]: decoding into
  u64/i64 and then numerically range-checking the narrowed result could not
  reject overlong encodings the spec deems malformed (a u32 spread across more
  continuation bytes than its width allows); per-width decoders that error once
  the shift reaches the target width's bit count catch the overlong case
  directly (diff).
