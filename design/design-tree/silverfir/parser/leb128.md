- LEB128 integer decoding is implemented in-tree (`utils::leb128`) rather than
  pulled from a crate; each decoder takes a byte slice and returns the value
  together with the number of bytes consumed.

- Signed and unsigned variants are provided, with width checks layered above to
  reject values that overflow the requested 32-bit or pointer-sized target.

## Facts

- 2024-01-25 (9e801234) rationale: the in-tree decoder is shaped around a
  hand-unrolled per-byte loop (a C reference of the unrolled form is kept in the
  source) and returns a consumed-byte count directly, so the reader advances its
  cursor without a separate I/O cursor object; this is the speed-oriented form
  the external crate's reader-based API did not offer (diff).

## Moves

- 2024-01-25 (9e801234) replaced [[leb128-crate]]: an external LEB128 crate
  drove decoding through an `io::Cursor`, an indirection unwanted on the hot
  parse path; a vendored decoder returning the consumed-byte count lets the
  reader advance directly (diff).
