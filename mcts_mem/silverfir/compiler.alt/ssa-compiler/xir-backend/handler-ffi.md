- Each handler takes the runtime context by shared reference and mutates only
  through interior mutability; the C trampoline's context and program-counter
  parameters and the handler return type are all `const`, encoding read-only
  execution in the type; a handler cannot scribble the dispatch state.

- The raw-pointer FFI boundary is converted to safe references once, inside the
  build-generated handler wrappers; individual handler bodies carry no
  raw-pointer unsafe of their own (`generate_handler_wrappers_rs`).

- All unsafe dereferences of the instruction pointer and its side-table metadata
  are centralized in one program-counter wrapper whose raw field accessors are
  private; handlers reach operands only through typed decode methods, and the
  safety argument is stated once rather than scattered (`Pc`).

- The extern handler declarations on the Rust side of the trampoline FFI are
  generated at build time from the declarative handler spec, and each generated
  extern is statically coerced to one hand-declared handler-signature type; any
  drift from the C ABI fails to compile.

## Facts

- 2025-10-13 (74b4ff9d) rationale: the FFI-shim accessors that hand the context to
  handler bodies deliberately return references with an unbounded lifetime rather
  than &self-bound ones, because a handler binds e.g. store/module and then, on
  the error path, calls trap_with needing &mut ctx while those references are
  still in scope — a &self-bound accessor would tie the immutable borrow to ctx
  and the later &mut ctx would not compile; the unbounded lifetime is what makes
  the safe-handler boundary expressible (code).

- 2025-10-15 (e7e1faff) rationale: the FFI pointer round-trip's soundness is
  verified at compile time by a never-executed handler built with the real macro
  and invoked under debug_assertions; if the handler contract (signature, borrows,
  interior mutability, lifetime flow) ever breaks, the call site fails to compile —
  this replaced an earlier standalone module that simulated the whole handler
  chain with mock handlers (code).

- 2025-10-15 (4e933d55) pitfall: a generated handler eagerly converts every
  pointer argument to a reference in its prologue before the body runs, so any
  direct Rust invocation must pass valid non-null addresses for all those args
  even when the body never touches them; the compile-time safety check was first
  wired up passing null for all pointer args, making &mut *null instant undefined
  behavior on every debug-build evaluation until the nulls were replaced with
  addresses of dummy stack variables (code).

- 2025-10-13 (eda174b0) pitfall: because the per-permutation handlers carry no
  operand decoding and read raw immediate fields whose meaning is fixed solely by
  what codegen packs into them, the handler's field decode and the emitter's field
  encode are an unwritten contract that must agree exactly; table.set silently
  transposed which field held the packed registers versus the table index (code).

- 2025-11-12 (86722d05) pitfall: a Sig_2_1 handler must read its operands from the
  register slots in the order the codegen permutation lays them down; table.grow's
  handler read its two operands in the reverse order, silently swapping the
  arguments (code).

- 2025-11-12 (2635f2c4) pitfall: a 1-in/1-out handler that 'passes a value
  through' must still write its declared output slot — the ref.as_non_null handler
  only read its input and never wrote the destination, so when register allocation
  assigned the result a different slot the output was left stale; an
  output-producing handler's contract is to write its destination slot, not to
  assume input and output share one (code).

- 2025-09-18 (a20ef41c) rationale: each handler is split across the FFI boundary —
  the per-op preserve_none musttail wrapper is generated by a single C macro that
  calls a Rust impl function taking the hot values by out-pointer, so handler
  bodies stay tiny and the dispatch convention is defined in exactly one place
  (code).

- 2025-09-29 (1250e6e1) rationale: each Rust handler is statically checked against
  the bindgen-generated handler signature type by a const binding inlined into the
  handler-defining macro, so any drift between a handler's Rust signature and the
  C-defined tail-call ABI fails to compile — replacing a hand-maintained standalone
  list of signature assertions with a per-handler self-check (code).

- 2025-09-29 (fde6bdd2) rationale: wildcard allowlists in the bindgen build step
  generate every op handler extern declaration, so the lowerer and tests use the
  generated bindings instead of hand-written extern blocks that previously had to
  be kept in sync and could drift from the C ABI (code).

- 2025-10-28 (06d9d4fb) pitfall: an explicit-destination handler must write its
  result through the destination slot, never through an input slot; the i64 shl and
  shr_u handlers wrote back into the first input, which is correct only in
  permutations where the destination aliases that input and corrupts the result
  (and the window slot-occupancy model) when the destination is a distinct slot
  (code).

## Moves

- 2025-10-15 (0d24ab09) replaced [[raw-nonnull-ctx]]: the old Ctx stored
  Store/Module/Func as NonNull and handed out unbounded-lifetime references
  through unsafe accessors so that a handler could re-borrow ctx mutably (e.g. to
  set the error), which defeated the borrow checker across the FFI boundary;
  making the fields real &'a borrows and moving the mutable state (error, regs)
  into Cell/RefCell lets every handler take &Ctx and mutate through interior
  mutability with no unbounded-lifetime unsafe (code).
